# Публикация Perekup Market

Игра требует сервер Node.js, постоянное соединение SSE и постоянный диск для SQLite. Обычный статический хостинг вроде GitHub Pages для неё не подходит.

## Хостинг на Cloud.ru (Container Apps + Object Storage)

Игра уже собирается в Docker-образ `perekup.cr.cloud.ru/perekup-market` при каждом пуше в `main` (GitHub Actions). Разворачивать её нужно через сервис **Container Apps**, а базу хранить в **Object Storage (S3)**.

### Почему «не запускается ревизия» и «пропадает база»

1. **Container Apps не даёт постоянный диск.** Файловая система контейнера эфемерна: при каждом новом запуске ревизии каталог `/data` пуст, а SQLite-файл `game.db` стирается. Аккаунты и прогресс пропадали именно из-за этого.
2. **Контейнеры не запускаются от root.** Сервис отклоняет образы, работающие под root («access denied»). В Dockerfile теперь указан `USER node` (UID 1000).
3. **Порт.** Платформа сама подставляет переменную `PORT` из поля «Порт» при создании контейнера — приложение слушает её автоматически. Главное, чтобы поле «Порт» было заполнено (укажите `4173`).

### Что сделано в проекте

- `s3-sync.js` — синхронизация базы с S3 без единой зависимости: при старте контейнер скачивает снимок `game.db` из бакета, во время игры выгружает его каждые 60 секунд, а при остановке ревизии (SIGTERM) сохраняет финальную версию.
- Если каталог `/data` недоступен для записи, сервер не падает, а переключается на `/tmp` (с предупреждением в логах).
- `PEREKUP_RESET_ALL=1` больше не затирает восстановленную базу: сброс выполняется только когда нет ни локального сохранения, ни снимка в S3.

### Шаги развёртывания

1. **Ключи S3.** В консоли Cloud.ru: Хранение данных → Object Storage → ключи доступа (персональный ключ или ключ сервисного аккаунта). Сохраните Key ID (вид `tenant:keyid`) и Key Secret.
2. **Создайте Container App** из образа в Artifact Registry (`perekup-market`, тег `latest`). Укажите порт `4173`. Привилегированный режим включать не нужно.
3. **Масштабирование: минимум 1, максимум 1 реплика.** SQLite допускает только одного «писателя»: при двух копиях базы разъедутся, и данные потеряются.
4. **Добавьте переменные окружения** (секреты — через ссылку на секрет, не открытым текстом):

```text
PEREKUP_S3_BUCKET=имя-вашего-бакета
PEREKUP_S3_ACCESS_KEY_ID=<Key ID вида tenant:keyid>
PEREKUP_S3_SECRET_ACCESS_KEY=<Key Secret>
```

Опционально (значения по умолчанию подходят для Cloud.ru):

```text
PEREKUP_S3_ENDPOINT=https://s3.cloud.ru
PEREKUP_S3_REGION=ru-central-1
PEREKUP_S3_KEY=game.db
PEREKUP_S3_SYNC_INTERVAL_MS=60000
```

5. **Проверка.** В логах ревизии должно появиться `S3_SYNC_ENABLED`, после перезапуска — `S3_RESTORE_OK`. Эндпоинт `/api/health` показывает `dataDir` и `s3Sync`. Зарегистрируйте игрока, перезапустите ревизию — аккаунт должен остаться.

### Перенос старой базы

Если нужно продолжить с существующей базой (например, с локального сервера, файл `data/game.db`), загрузите её в бакет как объект с именем `game.db` **до** первого запуска новой ревизии — сервер при старте увидит снимок и восстановит состояние.

### Частые ошибки ревизии (из документации Cloud.ru)

- `127.0.0.1:xxxx: connect: connection refused` — порт в настройках контейнера не совпадает с портом приложения. Проверяется в разделе «Ревизии → Общие параметры».
- `access denied` — попытка запуска от root; в текущем образе уже `USER node`.
- `failed to start container… exec` — неверно указана команда точки входа; оставьте поле пустым (образ сам запускает `node server.js`).
- Образ должен быть собран под `linux/amd64` (GitHub Actions собирает именно его).

## Рекомендуемый вариант: Railway

1. Создать пустой репозиторий на GitHub и загрузить в него содержимое папки `perekup-market`.
2. В Railway выбрать `New Project` → `Deploy from GitHub repo` и указать репозиторий игры.
3. После создания сервиса открыть его настройки и добавить `Volume`.
4. Указать точку подключения тома: `/data`.
5. В `Variables` проверить переменную `PEREKUP_DATA_DIR=/data`. В Docker-образе она уже задана, вручную менять её обычно не требуется.
6. В разделе `Networking` нажать `Generate Domain`.
7. Открыть выданный адрес вида `https://имя.up.railway.app` и проверить регистрацию двух игроков.

Важно: без Volume база будет находиться во временной файловой системе и может исчезнуть при следующем развёртывании. Один сервер должен иметь ровно один подключённый том `/data`.

## Перенос текущих аккаунтов

В рабочей версии база находится в `data/game.db`. Она намеренно исключена из Git и Docker-образа, чтобы публичная публикация не раскрывала локальные аккаунты и PIN-хеши.

Для нового публичного сервера безопаснее начать с чистой базы. Если потребуется перенести текущий прогресс, нужно отдельно загрузить `game.db` в корень Railway Volume `/data` до первого публичного запуска.

## Проверка после публикации

- Главная страница должна отвечать по HTTPS.
- `https://ваш-домен/api/health` должен вернуть JSON со `status: "ok"`.
- После регистрации и перезапуска сервиса аккаунт должен сохраниться.
- Две вкладки должны видеть изменения рынка и чата без ручного обновления.

## Обновления игры

После отправки новой версии в основную ветку GitHub Railway автоматически пересоберёт сервер. Подключённый `/data` не заменяется, поэтому SQLite и прогресс сохраняются.

## Приём платежей через YooKassa

1. Зарегистрировать магазин в YooKassa и дождаться его проверки.
2. В Railway → `Variables` добавить `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` из кабинета YooKassa.
3. Добавить `PEREKUP_PUBLIC_URL=https://ваш-домен` без завершающего слеша.
4. В кабинете YooKassa указать URL уведомлений `https://ваш-домен/api/payments/webhook` и событие успешного платежа.
5. Выполнить тестовый платёж минимального пакета и проверить начисление после возврата в игру.

Секретный ключ нельзя добавлять в GitHub или клиентский JavaScript. Пока обе переменные YooKassa не настроены, кнопки покупки честно показывают статус «скоро».

## Реальная реклама

Сайт поддерживает Рекламную сеть Яндекса и Google AdSense. Сначала зарегистрировать площадку, дождаться модерации и создать два адаптивных блока: для рынка и гаража.

Для РСЯ добавить в Railway:

```text
PEREKUP_AD_PROVIDER=yandex
PEREKUP_AD_MARKET_SLOT=R-A-XXXXXXXX-X
PEREKUP_AD_GARAGE_SLOT=R-A-XXXXXXXX-X
PEREKUP_ADS_TXT=строка ads.txt из кабинета РСЯ
```

Для AdSense:

```text
PEREKUP_AD_PROVIDER=adsense
PEREKUP_ADSENSE_CLIENT=ca-pub-XXXXXXXXXXXXXXXX
PEREKUP_AD_MARKET_SLOT=числовой ID блока
PEREKUP_AD_GARAGE_SLOT=числовой ID блока
PEREKUP_ADS_TXT=google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0
```

Если ID не заданы, сторонний рекламный скрипт не загружается и пустая заглушка не показывается. После настройки проверить `/ads.txt` и оба блока с отключённым блокировщиком рекламы.

## Появление в Google

1. Желательно подключить собственный домен в Railway: он стабильнее и лучше запоминается, чем технический домен `up.railway.app`.
2. Добавить домен в Google Search Console и подтвердить владение через DNS-запись. Для технического Railway-домена можно использовать проверку HTML-тегом, добавив выданный Google тег в `<head>` файла `public/index.html`.
3. В Search Console открыть раздел `Файлы Sitemap` и отправить `https://ваш-домен/sitemap.xml`.
4. Через `Проверку URL` запросить индексирование главной страницы.
5. Добавить содержательное описание игры на внешних площадках и ссылки на сайт. Индексация обычно занимает от нескольких дней до нескольких недель и не гарантирует высокую позицию.

В проект уже включены `robots.txt`, `sitemap.xml`, canonical, Open Graph и структурированные данные `VideoGame`. При переходе на собственный домен заменить старый URL во всех этих файлах.
